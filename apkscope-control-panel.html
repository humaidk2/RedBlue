ApkScope LOCAL · SEALED

Configure the sealed APK-investigation sandbox: local LLM, egress allowlist, and the decompile toolset. This page generates the three policy files and reads status.json to show what's live. Everything runs offline.

Opened as a file: use Download and move files into the repo yourself. Run ./apkscope.sh panel to get Save to repo, live status, and the LLM test.

Local LLM (Pi harness → Ollama / LM Studio)

Point Pi at a model on this machine (localhost) or on one box on your private LAN (IP address). Nothing is sent to any cloud provider. Inside the sandbox, Pi reaches it only through llm-gateway, which forwards to that one host:port.

Not tested
Accepted endpoints: localhost, 127.0.0.1, host.docker.internal, or a private IP (10/8, 172.16/12, 192.168/16). validate.sh refuses anything else. Match the context window to the server's (Ollama: OLLAMA_CONTEXT_LENGTH; LM Studio: the model's Context Length, which the gate checks). The browser test needs the server to allow CORS (LM Studio: Enable CORS). Either way, status.json is the source of truth.

Egress allowlist (hosts)

Default-deny. Only these hosts can be reached, and only from the model's shell tools, over HTTPS. The model endpoint has its own route, so leave this empty for a fully air-gapped run. Generates ai-proxy/filter.

    Each host also allows its subdomains. Local, LAN, and IP destinations are refused here and again by validate.sh.

    Decompile & analysis tools

    Tick the tools to install into the harness image, then re-run ./apkscope.sh setup. The gate refuses to start if the image is out of date. Checkmarks on the left come from status.json. Generates tools.txt.

    Status

    Run ./apkscope.sh health. It runs healthcheck.sh inside the sealed network, probes the seal, and writes status.json next to this page.
